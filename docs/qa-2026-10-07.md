# BoothPlus 호환성 개선 검증 (2026-10-07)

## 환경과 범위

- dot의 클라우드 PC에서 실행했다. 사용자 Mac을 사용하지 않았다.
- 최초 패치 기준: `75bf4d8caac7bb7f62c4bede953825999edb123e`; 최종 통합 기준: PR #29가 병합된 `1cf74c4712f77e8c832b6fc4d7f20aa7dd855516` (`dev`)
- 백엔드 계약 확인 커밋: `a4302ff89708f7649667e368834f2110304b8676`
- Node.js 24, Vitest 5, React 19, WXT 0.20, happy-dom 20
- 운영 리뷰·계정 설정·인증 정보를 변경하지 않았다. API·로그인·세션 테스트는 합성 데이터만 사용한다.

## 자동 검증

통합 후 결과: **16개 파일의 JavaScript/TypeScript 검사 169개 + Python 패키징 검사 4개 통과**. TypeScript·Chrome MV3·Firefox MV2 빌드와 ZIP 내용 검증, 고정 lockfile 설치가 통과했다. 아래 초기 DOM 확인은 실제 확장 설치 검증과 구분한다.

실행 명령:

```sh
npm run test
npm run compile
npm run build
npm run build:firefox
node_modules/.bin/vite build --config preview.vite.config.ts
git diff --check
```

React 테스트는 컴포넌트를 실제 DOM 트리에 렌더링하고 버튼·입력 이벤트를 발생시킨다. React Query와 삭제·저장 Promise의 완료 순서는 실제 구현을 사용한다. DOM은 happy-dom이며 네트워크·브라우저 확장 API·인증은 모의한다. 따라서 Chromium 렌더링이나 설치된 확장 테스트가 아니다.

검사 항목:

- 리뷰 로딩·목록 조회 실패·재시도·빈 목록·미등록 상품을 구분
- 비로그인 및 내 리뷰 조회 중에는 폼 변경/제출을 제한
- 500자 작성, 501자 제출 거절, 신규 작성/기존 수정 구분, 평점 전달
- 삭제 요청이 대기 중이면 폼 유지, 실패하면 초안 유지, 성공 후에만 폼 초기화·목록 갱신
- 로그인 취소 후 재시도, 대기 중 로그인/저장 버튼 재클릭 방어
- 로그아웃 완료를 기다리고 실패 시 초안을 유지
- `403 + message=forbidden` 사용자명 안내와 다른 권한 실패를 구분
- 계정 설정 열기·실패 처리, 페이지 추가 조회, IntersectionObserver 정리와 재마운트
- 실제 WXT shadow-root 도우미의 삽입 위치·구매 영역 비변경·컨텍스트 해제·반복 마운트/해제
- 동시 401 요청의 단일 갱신·각 요청 재시도, 갱신 중 로그아웃/새 로그인 시 이전 요청 재전송 방지
- 403/409/429/500/503 및 네트워크 단절 시 쓰기 요청을 자동 재전송하지 않음
- content script에 identity API가 없어도 백그라운드 메시지로 OAuth 반환 주소를 얻음
- 잘못된 OAuth state/반환 주소/토큰 본문을 거절
- 합성 미리보기의 외부 네트워크·쓰기 차단

## 검사 중 발견해 수정한 결함

로그아웃이 진행 중일 때 기존 리뷰의 삭제 버튼이 계속 활성화되어 있었다. 버튼과 삭제 핸들러 양쪽에서 현재 편집 가능 여부와 요청 대기를 확인하도록 수정했다. 회귀 검사에서 로그아웃 중 DELETE가 호출되지 않는 것을 확인했다.

## 실제 클라우드 브라우저에서 확인한 것

읽기 전용으로 다음 페이지의 현재 DOM을 확인했다.

- https://booth.pm/ko/items/6571299
  - `.primary-image-thumbnails`: 1개
  - `#variations`: 1개
  - `booth-review`: 0개
- https://jingo1016.booth.pm/items/5058077
  - `.primary-image-thumbnails`: 1개
  - `.cart-btns`: 1개
  - `booth-review`: 0개

이 결과는 두 상품 페이지에 삽입 기준 요소가 있다는 뜻이다. 확장이 설치되거나 리뷰 UI가 실제로 실행되었다는 뜻은 아니다.

## 미검증과 남은 작업

- 클라우드 브라우저는 `chrome://extensions` 접근을 URL 프로토콜 정책으로 거절했다.
- `http://127.0.0.1:4173` 미리보기 접근은 `ERR_BLOCKED_BY_CLIENT`로 거절했다.
- 현재 지원 기능에는 확장 로드 전용 기능이 제공되지 않았다. 제한을 우회하지 않았다.
- 설치된 확장의 실제 화면·접근성·Discord 로그인/취소·서비스 워커 재시작·실제 리뷰 CRUD는 확인하지 못했다.
- 초기 검사에서 발견한 한 번만 mount하는 제한은 이번 통합에서 수정했다. 이제 보드·칩의 지연 앵커/동기 교체/제거/상품 이동/컨텍스트 무효화 시 재연결과 정리를 합성 DOM에서 확인했다. 실제 브라우저의 동적 전환 검증은 여전히 필요하다.
- 설치 가능한 승인된 브라우저 테스트 경로가 제공되면 실제 확장을 로드하고 위 시나리오를 통합 검증해야 한다. 쓰기 검사는 별도 테스트 계정/비운영 데이터에서 수행한다.
- 추적 이슈: https://github.com/vrc-booth/vrc-booth-extension/issues/31
- PR #29의 칩·공용 캐시를 최신 dev 기준으로 통합하고 두 실제 React 루트의 공유 요청·닫기·포커스를 합성 DOM에서 확인했다.


## #30–#32 후속 구현

- 3.3.0 로컬 후보에 칩/호환성/세션/DOM 수명주기를 통합했다. 같은 상품의 쿼리/해시 변화는 캐시 키를 바꾸지 않는다.
- 다른 탭의 로그인/로그아웃을 storage 이벤트로 감지해 이전 계정의 profile·myComment·myComments 캐시와 폼을 초기화한다. 같은 세션의 토큰 회전에는 불필요한 초기화를 하지 않는다. 이전 요청의 늦은 응답이 새 캐시를 채우지 않는 검사와 보드가 없는 동안 놓친 storage 이벤트를 재마운트에서 조정하는 검사를 추가했다.
- PR CI와 읽기 전용 수동 산출물 준비, 정확한 ZIP 이름/manifest/확장 ID/권한/해시 검사, 버전·기존 태그·QA 게이트, 변경 기록/복구 문서를 작성했다.
- 코드의 로컬 통합은 완료했지만 원격 push/리뷰와 #31 실제 설치 검증, Firefox 게시자 설정/서명은 아직 남아 있다. 이슈 전체 완료나 배포 가능 상태로 처리하지 않는다.
