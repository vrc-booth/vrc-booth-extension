- 공식 백엔드 main 2.5.20: [`1ec590ea159622fd140de97a0fae962410d662d0`](https://github.com/vrc-booth/vrc-booth/tree/1ec590ea159622fd140de97a0fae962410d662d0)
- 공식 프런트엔드 dev: [`a4d266f42569afb332941c3b9c090813283808fb`](https://github.com/vrc-booth/vrc-booth/tree/a4d266f42569afb332941c3b9c090813283808fb)
- 사용자 프로필 사진 자리/스켈레톤/기본 사진 파일/폐기된 hideAvatar 타입을 제거했다. 상품·상점 이미지와 VRChat 아바타 정보는 대상이 아니다.
- 상품·인증·사용자명 API는 유지한다. 리뷰 목록/내 리뷰/생성/수정/삭제만 이미지 지원 `/api/v2/review`로 옮겼다. 서버는 1 기반 고정 20개 페이지이고 `limit`을 무시하므로 보드·요약 칩·계정 목록의 페이지 크기도 20으로 맞췄다.

## 확인한 계약

- POST `/api/v2/review/image`: 인증된 multipart `file`, 성공 시 `{ image: { id, url, width, height } }`.
- 최대 5장, 장당 8MiB, 정적 JPEG/PNG/WebP. 서버는 실제 바이트와 이미지 디코딩을 검증한다. 최소 64×64px, 한 변 최대 8000px/총 4천만 픽셀; 애니메이션 PNG/WebP는 거절한다. 저장 시 최대 1600px WebP로 정규화한다.
- 리뷰 POST/PUT에는 표시 순서대로 `imageIds`를 보낸다. PUT에서 생략하면 기존 목록 유지, `[]`면 전체 제거다. 기존 익명 리뷰 상태도 유지한다.
- DELETE `/api/v2/review/image/{id}`는 본인의 미연결 업로드만 삭제한다. 기존 첨부를 폼에서 제거해도 먼저 삭제하지 않고, PUT 성공 후 분리된 ID만 정리한다. 정리 실패는 리뷰 저장 성공을 되돌리지 않으며 15초로 제한한다.
- 공개 URL의 호스트는 서버 설정에 따라 달라진다. 반환된 HTTPS 주소만 허용하고 인증 정보 포함 URL, javascript/data/blob/http 주소는 거절한다. 렌더링은 React escaping, lazy image, no-referrer, noopener/noreferrer를 사용한다. 숨김 공개 리뷰의 내용/이미지는 표시하지 않는다.
- 형식/크기/검열/한도/서비스 오류는 서버 결과로 안내한다. 클라이언트의 파일명/MIME 검사는 서버 검증을 대체하지 않는다.

## 검증 범위

Node.js 24.19.0, 현재 고정 의존성, Vitest 5.0.3, happy-dom, WXT 0.20.11에서 실행했다. 이 실행 세션에는 Bun 실행 파일이 없어 기존 Bun 설치 의존성의 Node 진입점을 직접 실행했다. CI는 Bun 1.4.2 고정 설치를 별도로 검증한다.

- 전체 JS/TS 검사 **21개 파일, 485개 통과** (기준 437개에서 이미지/세션 회귀 48개 추가), 타입 검사, Chrome MV3/Firefox MV2 빌드 통과
- Python CWS 불변 산출물 **26개**, 패키지/릴리스 **10개** 검사 통과
- 네트워크 쓰기 차단 로컬 미리보기 빌드 통과. 미리보기의 이미지 API는 자체 메모리 blob만 사용하며 실제 서버나 파일 업로드를 하지 않는다.
- v2 응답 wrapper/경로/20개 페이지, multipart boundary/header, 401 갱신과 동일 FormData 재사용
- 5장/8MiB 경계, 지원 형식, 잘못된 업로드 응답/URL, 공개 숨김 리뷰/익명 사용자
- 업로드 전 로컬 미리보기, 파일 제거/종료 시 object URL 해제
- 기존 이미지 유지/제거/순서, 익명 상태 유지, 업로드 및 저장 실패 후 초안 유지
- 중간 업로드 실패 후 성공한 업로드 재사용, 실패한 미연결 이미지 삭제/404 복구
- 같은 이벤트 루프의 반복 제출, 종료/계정 전환 중 늦은 응답과 후속 저장 차단
- 토큰 회전 시 초안 유지, 동일 사용자 재로그인 시 같은 리뷰 ID 재수화
- 로그인 시 빠른 내 리뷰/느린 공개 리뷰 조회 경합, 이전 로그아웃 조회가 늦게 끝나도 새 계정의 저장된 첨부 유지, 내 리뷰 조회 실패 시 제출 차단/재시도
- 저장 응답 손실 시 읽기 전용 조회로 결과 확인. 동일 결과면 성공 처리하고, 다른 저장본이 있으면 현재 초안은 유지하며 다음 명시적 재시도에 PUT을 사용한다. 자동 쓰기 재시도는 하지 않는다.

독립 코드 리뷰에서 위 로그인·재로그인·로그아웃 경합을 합성 DOM으로 재현해 수정했으며, 최종 재검토에서 남은 차단 결함이 없었다. `git diff --check`도 통과했다.

## 제한

이 검증은 모의 네트워크/합성 파일과 실제 React DOM 로직에 대한 검사다. 운영 리뷰 작성/이미지 업로드, 로그인 자격 증명 변경, 사용자 Mac 사용, 스토어 게시를 하지 않았다. 공식 저장소 버전이 현재 배포된 버전과 같다는 보장은 없으며 운영 이미지 API 호출은 접근 제한 때문에 검증하지 못했다. 설치된 Chrome/Firefox의 실제 BOOTH 페이지, Discord 로그인, CORS/multipart 전송, 이미지 디코딩·검열·저장소 연동은 별도 비운영 테스트 계정 QA가 필요하다. 기존 배포 차단 조건은 그대로 유지한다.
